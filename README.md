# 创维 E900V21C（S905L / P211）Android 6.0.1 实机适配与救砖笔记

> **真实设备、真实失败、真实恢复。** 2026-11-16 完成一次山东联通创维 E900V21C 的 Android 4.4.2 → Android 6.0.1 迁移，在保留 / 恢复原机引导链并校正系统分区适配后，机器进入 Android 桌面。这里分享实测路径、踩坑和严格的验收边界，不把一次成功包装成“所有 S905L 通刷”。

**项目状态：实机启动 PASS｜教程公开｜无可安全通刷的一键 ROM。**

## 一分钟看结论

目标机器（**仅这台机器的实测配置**）：

| 项目 | 记录 |
|---|---|
| 外壳铭牌 | 创维 E900V21C，山东联通版 |
| SoC / 板型 | Amlogic S905L（GXL），`gxl_p211_1g` / `p211` |
| 内存 / 存储 | 标称 1GB RAM / 8GB eMMC |
| 原系统 | Android 4.4.2 |
| 实际启动的新系统 | **Android 6.0.1 / API 23**，Linux 3.14.29 |
| 实测显示 | HDMI 1920×1080@60Hz（康佳电视） |
| 实测管理 | 以太网、ADB、开机完成标志、软件重启 |
| 实测媒体 | H.264 1080p 硬件解码进入 PLAYING、AAC 48kHz 输出链；非长期压测 |
| 其它 | 原厂红外遥控器能开关盒子（用户实测）；蓝牙控制器存在反复超时问题 |

本次真正的适配关键不是“找到了一个名字包含 S905L 的包”，而是：

1. 原机 **P211 设备树**描述 14 个分区、`system` 640 MiB；通用 Android 6 候选包则描述 12 个分区、`system` 1 GiB。
2. 通用包 Android 启动镜像的第二阶段 DTB 只带 P212，不能按“都是 S905L”直接套用。
3. 通用引导区标识 `gxl g1614c0b`，原机备份为 `gxl gc9db010`。把它当成可以随意替换的组件，会造成黑屏和启动失败。
4. 我们最终使 **原机专属 FIP Bootloader** 回到 BootROM 实际读取的 eMMC 物理位置，并做到写后逐字节校验；搭配经过 P211/640MiB 适配的 Android 6 `boot`、`system` 与原机板级组件，成功启动。

> **请特别注意：** 这不是一套已经对陌生设备验证过的“傻瓜一键刷机包”。第一次尝试曾导致不能启动；后来的成功包含针对**本机备份**的引导修复。没有原机完整备份和恢复能力，不要贸然尝试。

## 最重要的避坑提示

**以下两个镜像都有真实实验记录，但都不能当成“亲测可直接一键通刷”的成品：**

| 镜像 | SHA256 | 本机结论 |
|---|---|---|
| `S905L_6.0.1_TWRP.img`（通用候选） | `5d199b575b9617b60f5a180ed14a98803bab2905b4c3445682fcb4ec87d5f16e` | **不建议原样全量刷**：引导、设备树和分区差异；曾进入 TWRP 循环 |
| `E900V21C_P211_Android6.0.1_USB.img`（2026-11-15 本机实验构建） | `fc64be1d185f7d94a24fc40988eaa09e6e87b88cf25a990a768cb08cdc866185` | **不是独立可用的最终安全包**：没有 Bootloader payload；实际 Windows GUI 擦除选项开启，刷后无 HDMI，需恢复原机 FIP |

**绝对不要**看到“烧录进度 100%”就认定刷机完成；要拔掉 USB 数据线，冷启动并验收 Android 版本、HDMI、网口、遥控器与重启。

尤其警惕 Windows USB Burning Tool 的 **Erase flash** 和 **Erase bootloader**：镜像内的 `aml_sdc_burn.ini` 写着 0，**不等于 GUI 里的选项也是 0**。本机事故恰恰证明两者会出现矛盾。

如果你只是想稳定使用电视盒子，**原固件能满足需要就不要为了升级而冒险刷写**。本仓库最有用的部分是**板型识别、备份、镜像审计以及黑屏复盘**。
