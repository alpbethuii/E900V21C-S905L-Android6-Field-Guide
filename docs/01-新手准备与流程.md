# 新手逐步指南：先认清主板，再决定刷不刷

> **读完本页不代表可以立即按 Start。** 本项目已经成功让**一台** E900V21C 运行 Android 6.0.1，但还没有公开一份“在另一台原厂机上直接烧录并成功冷启动”的最终可重复验证包。教程把**任何人都能安全做的准备工作**和**需要自行验证后才能执行的固件写入**明确分开。

## 第 0 步：先读这个结果

实际成功使用的组合不是“网上下载一个 S905L 安卓 6 镜像 → USB Burning Tool 全部默认勾选 → 点击开始”。我们经历过两类错误：

- 通用 Android 6 固件与 P211 板型分区不一致，发生 TWRP 循环。
- 后来做出的定制包虽可写入 `boot/system/recovery`，但 Windows 烧录 GUI 同时开启了擦除 Flash 和 Bootloader，原机引导链遭破坏，盒子黑屏。直到恢复原机专属 FIP 后才正常启动。

**如果你没有设备自己的原始 Bootloader/FIP 与数据备份，或没有恢复 WorldCup 模式的能力，请停在备份/鉴别阶段。**

## 第 1 步：准备物品

硬件：

1. **本机 E900V21C**（拍外壳铭牌和主板丝印；发到网上前遮住序列号与运营商业务编号）。
2. 原装或符合设备规格的供电适配器、HDMI 线和一台显示器 / 电视。**不要只靠刷机软件进度条判断成功。**
3. 一台 Windows 电脑、**确实能传数据**的 USB-A 公对公线（不是只有充电功能的线），并确认机顶盒的 **OTG/烧录口**。
4. 可能用得上的：串口 TTL 转 USB 适配器、能够进入 WorldCup 的硬件救援工具（仅在明确板型与电路的前提下使用）。

软件：

- Android Platform Tools（包含 `adb`）；
- PowerShell 自带的 `Get-FileHash`；
- 7-Zip 等压缩工具；
- Amlogic USB Burning Tool（本机见过 2.1.9.0 主程序、界面 2.2.0；**不是对所有电脑的版本推荐**）。

有线网络和本机 SSH/ADB 调试只是辅助，不是必须有家庭服务器才能操作。

## 第 2 步：只读确认“你手里的究竟是什么”

**先别断电、别短接、别运行擦除。** 在电脑上打开终端，执行：

```powershell
adb devices -l
adb shell getprop ro.product.model
adb shell getprop ro.product.device
adb shell getprop ro.product.board
adb shell getprop ro.build.version.release
adb shell getprop ro.build.version.sdk
adb shell cat /proc/cmdline
adb shell cat /proc/partitions
adb shell ls -l /dev/block/by-name
```

说明：

- `adb devices` 必须显示 `device`，不能是 `offline` / `unauthorized`。即使显示 `device`，也再运行一次 `getprop` 确认是真实响应而非缓存。
- 部分 Android 4 ROM 没有 `/dev/block/by-name`，该行报错不一定有故障；但**无法确认分区映射就不可贸然写分区**。
- 我们这台原机对应的是 `gxl_p211_1g`；刷入 Android 6 后报告 `ro.product.device=p211`、API 23。
- **S905、S905L、S905L2、S905L3、S905L3A 不可只看名称互刷**；E900V21C 与外观类似的其他型号，也不能凭商品标题视为相同 PCB。

对照下表：

| 检查项 | 本项目的已知值 | 你的设备不同怎么办 |
|---|---|---|
| 铭牌 | 创维 E900V21C | **停止**，别用此项目配方 |
| 板型 | GXL / P211 / 1GiB | **停止**，需重新审计 |
| 原 `system` 分区大小 | 640MiB | **停止**，需重新适配 |
| eMMC | 标称 8GB | **停止**，先核对真实布局 |
| 已有 Bootloader 完整备份 | 本项目有本机来源备份 | 没有就**不建议进入写入阶段** |

## 第 3 步：先做能恢复的备份

这一步比找 ROM 重要。

建议保留本机原始 `boot`、`recovery`、`system`、`dtb`、Bootloader/FIP、环境区（若实际存在）、分区表/设备树、必要的用户数据。**所有原始文件都存放在电脑或移动硬盘，至少两个存储位置；不要只留在准备被擦掉的盒子内。**

本项目确实备份了原系统的如下内容：

- `boot`：32MiB；
- `recovery`：32MiB；
- `system`：640MiB；
- Amlogic multi-DTB：256KiB；
- 本机引导备份及环境备份；后来从**原机备份**中确认并提取了供物理恢复使用的 896KiB FIP。

**为什么不提供网上常见的“一键备份 bootloader 命令”？** 原机当时没有完整记录 Bootloader/env 的源块设备路径与偏移，直到故障时才通过 BootROM/FIP 证据逐层确认。对另一台机器照抄 `dd if=/dev/...` 很可能备份错地方。请让熟悉 eMMC/MTD 的人先确认你的分区映射和源区间，并对原始备份生成 SHA256；未知就暂停。

你可以先安全地检查现有文件的哈希（**不写盒子**）：

```powershell
Get-FileHash -Algorithm SHA256 "D:\E900V21C-backup\boot.img"
Get-FileHash -Algorithm SHA256 "D:\E900V21C-backup\recovery.img"
```

`D:\E900V21C-backup\` **只是示例路径**。没有这些备份就不会自动生成。

## 第 4 步：判断你下载的包有没有板型/分区隐患

上游 S905L ROM 收集项目：[Ubuntu5020/AmLogic-S905L](https://github.com/Ubuntu5020/AmLogic-S905L)。其中的 `S905L_6.0.1_TWRP.img` 是**研究素材**，不能认作“E900V21C 一键包”。

我们确实检查过的候选包 SHA256：

```text
S905L_6.0.1_TWRP.img
5d199b575b9617b60f5a180ed14a98803bab2905b4c3445682fcb4ec87d5f16e
```

这份候选镜像的问题：

- 它的 Android `system` 稀疏镜像展开后为 **1GiB**，但本机 `system` 只有 **640MiB**。
- 启动镜像第二阶段含 P212 DTB，不是本机必需的 P211 配置。
- 含 TWRP 与非本机原厂 Bootloader；可能遇到 `/data` 无法挂载、反复进入恢复界面，或完全无画面。

**检查**：把固件放在电脑上，先校验下载 SHA256，再使用 Amlogic 镜像分析工具*离线*查看 `image.cfg`、DTB、`boot`、`system`、`recovery`、Bootloader，**不要把压缩包里的 IMG 直接用 `dd` 写进 U 盘或 eMMC**。它是 Amlogic 专用刷机容器，不是 Linux 磁盘镜像。

修改原理在 [第 02 页](02-适配原理与镜像.md)。**没有经过适配审查的镜像，绝不能进入第 5 步。**

## 第 5 步：进入 USB 烧录模式，只先识别设备

本机曾经通过 Windows 与盒子连接，观察到 Amlogic WorldCup **VID 1B8E / PID C003**。该枚举只证明设备处在烧录通讯模式，不表示镜像可用。

1. 让电视显示 HDMI，记录当前画面。
2. 找到 E900V21C 真正的 OTG 数据口，用 USB 数据线接 Windows 电脑。
3. 启动 Windows 设备管理器，观察是否出现 Amlogic/WorldCup 设备以及硬件 ID。需要驱动时，**优先使用签名可靠、版本匹配的驱动**；不要为了旧 C003 驱动关闭系统签名保护。
4. 若机顶盒仍正常开机，部分原版 U-Boot 可通过 `adb reboot update` 进入更新模式，但必须先确认 U 盘上没有任何自动烧录脚本。若失败，不要反复盲试。
5. 有硬件救援工具也**不要直接按网上“短接某两个点”的照片操作**：eMMC 芯片和 PCB 修订不同，短接错位会造成硬件损伤。
6. **观察到设备进入 WorldCup 后，到此先暂停；不要点击 Start。**

本项目还使用了 Windows `usbipd` 将 USB 设备转给 Linux Amlogic 工具进行诊断；这属于高级分析链路，不是普通用户必须复刻的步骤。

## 第 6 步：烧录工具里的致命设置（必须亲眼核对）

当且仅当你**已经有本机专属备份、适配过的镜像和恢复方案**，才可检查烧录配置：

- 从软件菜单导入已经核验 SHA256 的 IMG 文件；导入成功≠可启动。
- 打开擦除设置，**确认 Erase flash 和 Erase bootloader 不是默认选中**。每次重开软件都重新确认。
- 不要用“镜像里 `erase_flash = 0`”代替检查 Windows 软件界面；本次事故里 GUI 实际仍然保存 `EraseFlash=1` 和 `EraseBootLoader=1`。
- 若镜像**没有** `bootloader.PARTITION` 却请求擦 Bootloader，刷完后设备可能毫无画面。本机就发生了这一幕。
- 不要进行 `disk_initial`、全盘擦除或烧写陌生人的 `FIP/DDR/UBOOT`。
- **本项目的 2026-11-15 定制 IMG 不可作为新手直接按 Start 的刷机包。**

**目前停止线：本仓库没有对其他原厂 E900V21C 完成过“未擦 Bootloader → 单次正常刷入 → 冷启动”的公开复现。因此，这一步不是可直接照做的已验证一键安装操作。** 需要真正可复制的整链验证后，才会更新本页。

## 第 7 步：只要发生过写入，必须独立验收

完成写入后，拔除刷机 USB 数据线，保留电源/HDMI/网线，按正确断电流程冷启动。逐项检查：

1. 是否有 HDMI 信号、能否进入 Android 桌面，是否还在 TWRP 循环。
2. Android 设置是否显示 6.0.1；ADB 检查 `getprop ro.build.version.release` 是否返回 `6.0.1`、`ro.build.version.sdk` 是否返回 `23`。
3. `getprop ro.product.device` 是否为 `p211`，`getprop sys.boot_completed` 是否为 `1`。
4. 以太网、USB、HOME/返回/原厂红外遥控、HDMI 音视频是否可用。
5. **第二次独立重启**后是否仍正常；再测试常用播放器和音频格式。

我们这台设备的客观结果列在 [实机验收清单](04-验收与已知问题.md)。

## 第 8 步：碰到故障不要急着再刷

- **HDMI 无信号 / 黑屏**：优先审计 Bootloader 是否被擦、FIP 是否匹配；不要先假定电视坏了。
- **反复进入 TWRP**：检查原版与新固件的 `/data`、`/cache` 挂载布局，以及 boot/recovery 分区。
- **工具 100% 成功，系统却不启动**：100% 仅表示烧录通信结束；设备树、DDR、FIP、分区还可能不兼容。

按 [故障恢复文档](03-故障恢复.md)处理。**不要拿他人的完整 FIP 或备份“试一试”。**

---

### 这一页的承诺与边界

这份指南尽量使新人知道**准备什么、点哪里之前先看什么、每一步应得到什么结果、看到什么就必须停止**。它并不冒充一个尚未通过跨设备验证的通用救砖器。只有真正适配本机且有独立冷启动结果的镜像，才能被称为“可刷机成果”。
