## 为什么没有“完整 ROM 下载地址”？

**这个仓库公开的是原创文档和排障方法，不是固件镜像分发站。**

Android 6 镜像中包含 Android 用户空间、厂商二进制驱动、Bootloader、设备树、第三方组件与可能带设备特定数据的分区。其授权情况复杂；尤其是“从用户的原机备份抽出的 Bootloader/FIP/Recovery/DTB”，不应当当成公共文件随意转发。

因此本仓库**不包含**：

- Amlogic 全量刷机 `.img` / 压缩分卷；
- 本机 `bootloader`、`recovery`、`system`、`dtb` 或 FIP 原始二进制；
- 本机备份、身份信息、密钥、unifykey、安全芯片数据；
- 运营商 IPTV 业务密钥、M3U/EPG 私有源、Emby 账号；
- 原系统 OTA、未经审查的第三方 APK 或 Windows 驱动安装包。

原始文档、SHA256、构建对比和**有明确事实依据的命令格式**足以帮助后来者先做匹配和风险判断。希望复现者应该从有权使用的固件与**自己的原机备份**出发，而非复制别人的 Bootloader。

## Android 6.0.1 安全边界

本机验收的 Android 6 固件是旧版 `userdebug / test-keys` 系统；现场观察到 `ro.secure=0`、可授权的高权限 ADB，原 ROM 安全补丁年代久远。它适合作为**隔离网络内的老旧设备实验和调试终端**，不应承担敏感账号或对外服务。

最低限度建议：

1. **绝不**在公网路由器、Lucky/Nginx 反向代理或 UPnP 暴露 TCP `5555`（ADB）。
2. 只允许可信电脑/内网管理端访问 ADB；不需要远程调试时关闭网络 ADB。
3. 不在这种系统内长期登录银行、支付、私人邮箱或重要云盘账号。
4. 使用合适的设备隔离、最小权限和局域网 ACL；对 Android 6 的系统漏洞保持现实预期。
5. 使用不同的密码与身份凭据，不要把家庭网络截图、日志或配置原样发到 Issue。

本次项目中，蓝牙控制器初始化失败、节目单数据映射问题、部分播放器/遥控场景未全面验收。**不要把 ROM 能启动等同于所有功能、安全性、长期稳定性都已验证。**

建议 Issue 只填写以下已脱敏信息：

```text

SoC / 实际设备树名称：
RAM / eMMC 容量：
原 Android 版本：
原 system 分区尺寸：
所用镜像来源与 SHA256：
烧录工具版本、GUI EraseFlash/EraseBootLoader 状态：
是否正常显示 HDMI Logo / 桌面：
```
