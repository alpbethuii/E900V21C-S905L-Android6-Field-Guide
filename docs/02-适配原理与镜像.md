# 技术说明：P211 设备树、640MiB 分区、Android 6 内核与原厂 FIP

**范围：** 对一台山东联通创维 E900V21C 进行的现场记录。这里写的是可追溯的**镜像结构**与**检查方法**，不是“任何 S905L 通刷规则”。

## 1. 最难的地方：型号名相同，硬件布局不同

原机：Android 4.4.2，`gxl_p211_1g`，原 `system` 分区 **640MiB（671,088,640 字节）**，14 个分区（包括 `ghost`、`info`）。

下载的通用 Android 6.0.1 包：

- `system` 文件系统约 **1GiB（1,073,741,824 字节）**，原包 DTB 按 1GiB `system` / 12 分区建模。
- `boot.PARTITION` 的第二阶段设备树只有 `gxl_p212_1g` 与 `gxl_p212_2g`。
- 携带 TWRP 与另一套 Bootloader（`gxl g1614c0b`）；原机 Bootloader 标识为 `gxl gc9db010`。

**不能直接把 1GiB `system` 数据写进 640MiB 分区**，也不能把 P212 DTB 改个文件名当 P211 用。

### 诊断要点

- Android 使用的 `/dev/dtb` 可能是 *multi-DTB* 容器，不是一棵单独的 DTS。解析时要找准 `gxl_p211_1g` 的 FDT 条目，确认真正的 `partitions`。
- 检查 Android `boot.img` 是否包含第二阶段 DTB；若替换或重组该阶段，必须重新生成并验证 Android boot-image 头部校验。
- 分区调整不只是 `resize2fs`：还要确认 ext4 一致性、sparse 声明的展开大小、镜像重新打包后可无损回拆。
- Bootloader、DDR 初始化代码和板上 Wi-Fi/音频驱动都可能与 PCB 修订绑定。不能因为 Linux 内核都是 3.14.29 就默认兼容。

## 2. 我们制作过的 P211 定制包：结构和限制

2026-11-15 的**实验包**：

```text
E900V21C_P211_Android6.0.1_USB.img
size:   547766340 bytes
SHA256: fc64be1d185f7d94a24fc40988eaa09e6e87b88cf25a990a768cb08cdc866185
```

其设计目标：

| 组件 | 来源 / 处理 | 验证 |
|---|---|---|
| `boot.PARTITION` | Android 6.0.1 候选 kernel/ramdisk + 原机 P211 multi-DTB 第二阶段 | 32MiB，boot header 校验重算通过，SHA256 `4a443537c87c455882c5e63a971a7a48bac4abd8a009fe11ec6f17f198dd2467` |
| `system.PARTITION` | 候选 Android 6 system 从 1GiB 缩到 640MiB，再转换 sparse | 展开大小恰好 671088640B；SHA256 `108e9bef767b65d7ffc6ba50471224fcbe86cd856525832262c9bff342aeeb1e` |
| `recovery.PARTITION` | 原机 4.4.2 stock recovery，而非 TWRP | 32MiB，SHA256 `f98954787cd07a7c885a28d195f19d21c01b71a4a187243ab10ad128f32eb13c` |
| `meson1.dtb` | 原机 multi-DTB，包括 P211 与原分区表 | 256KiB，SHA256 `59960d0860c87f02273c3a20d030d13c9d5d13de5cec1bd924794faee0051d15` |
| USB loader | 从经设备枚举使用过的 GXL 刷机包保留 | 用于临时 Windows/WorldCup 通讯；**不等于可替换 eMMC 原厂 Bootloader** |
| Bootloader payload | **故意没有** `bootloader.PARTITION` | 镜像需要原机引导链保持完好；软件 GUI 擦除它会导致严重故障 |

实际内部 `image.cfg` 只请求烧写 `boot`、`recovery`、`system`，另有 `meson1.dtb` 与 loader/manifest/INI 元数据。离线打包器 `aml_image_v2_packer` 返回 `Image check OK`；解包回读后的 recovery/system/dtb 文件 SHA256 匹配。

但是**“离线包校验通过” ≠ “刷机完成后一定启动”**。实际 USB Burning Tool GUI 仍执行了擦除相关阶段，引导链受损。最终系统能启动，是因为后续**恢复了本机原始 FIP**。这份实验 IMG **不要作为未改动的可直接刷机包传播**。

## 3. 640MiB system 适配的真实技术流程

以下仅表示**离线工程方法**，不指向盒子任何块设备：

1. 用 `simg2img` 把源 system sparse 展成 ext4 原始文件。
2. 在离线副本上跑 `e2fsck`，确认 ext4 文件系统一致。原候选镜像有过目录项一致性问题，检查不能省略。
3. 计算原硬件 `system` 能容纳的最大块数。例：640MiB / 4KiB = **163840** 块。缩容前必须确认实际已用数据量小于目标容量且保留可用空间。
4. 用 `resize2fs` 对离线文件系统缩容，精确控制 backing file 大小为 671088640B；再执行只读一致性检查。
5. 使用 `img2simg` 重新生成 Amlogic 容器所需 sparse payload；用 `simg2img` 回拆，核实 **字节完全一致**。
6. 用对应板级的多 DTB 重构 boot 镜像第二阶段，正确生成 Android header 校验；不应采用 P212 的默认第二阶段。
7. 将 **本机原始** recovery、multi-DTB 与适配后的 boot/system 按正确的 `image.cfg` 打包，做完整解包往返校验。

> 本仓库**没有**声称“以上 7 步可无条件得到可启动包”。Amlogic IMG 的具体打包命令、镜像元数据、工具版本、板级硬件身份都必须逐一检查；也没有将闭源镜像或原机签名/校验资料上传供复制。

可供研究的工具（不是对其完整固件的背书）：

- [natinusala/linux-amlogic-toolkit](https://github.com/natinusala/linux-amlogic-toolkit)（镜像解包/重建工具思路）；
- AOSP `simg2img`、`img2simg`；e2fsprogs 的 `e2fsck`、`resize2fs`；
- [Ubuntu5020/AmLogic-S905L](https://github.com/Ubuntu5020/AmLogic-S905L)（原始候选固件资料来源）。

这些项目的具体授权与使用条件各自独立。

## 4. 为什么恢复的是本机 FIP，而非任意通用 Bootloader

Amlogic GXL BootROM 需要从指定的 eMMC 用户区位置读取板级 FIP/BL2/DDR 引导材料。不同供应商 DDR、电源和板级引脚组合可以不兼容。

现场还原证据：

- 原备份为 4MiB 的 Bootloader 读取产物；首 512 字节为 0，`@AML` 标志位于文件偏移 528；
- 经边界验证，实际有效的原机 FIP 内容可以提取成 **896KiB**；
- 专门准备的本机 FIP SHA256：
  
  `a71f38458400b77b487ff4270e47b21edb810f61a90a3fcc9290f1a9a72cc775`

- 恢复后，以 **eMMC 用户区 LBA1** 开始的 **1792 扇区（896KiB）** 物理读回产物与原始 FIP 的 SHA256 逐字节相同；
- 后续 Android 6.0.1 实际正常进入桌面并完成软件重启。

重要边界：此 FIP 是**这一台机器**的备份，**不公开二进制文件，也不能当成别人机器的恢复包**。FIP 的字节分布、烧写目标、分区名与工具参数不应被当作其他 Amlogic 代际的通用规则。

## 5. 驱动到底有没有全部升级？

没有证据表明“所有驱动都升级到新版”。检查中部分内核模块 / Amlogic 解码组件（如 `8189fs.ko`、`8189es.ko`、`mali.ko`、`dhd.ko`、`libamvdec.so`、`libamcodec.so`、音频 HAL）在原系统与 Android 6 候选间是相同二进制。我们选择尊重 ABI 兼容性，不做“只为了版本号而覆盖”的动作。

因此准确表述应是：**Android 6.0.1 系统 + 较新的候选内核/ramdisk + 本机 P211 硬件描述/原机引导链**。不是“手工逐项升级所有厂商驱动”。

## 6. 能否进一步做成发布版？

需要独立实验再次复现**一次性正向安装**：

- 原机 4.4.2 → 确认同板型/同分区；
- 自机完整备份可独立恢复；
- 正确 GUI 烧录开关不擦 bootloader/全盘；
- 写入完成，拔 USB、独立冷启动；
- Android 6.0.1、1080p HDMI、音频、网卡、原厂红外、USB、二次重启均通过；
- 不依赖随后单独写 FIP 才能启动；
- 同时审查 ROM 版权/第三方驱动再分发权。

**在这组验证成立之前，不把 2026-11-15 的实验包升级成“稳定版下载”。**
